# P5 W3 — Observação legítima de HTTP 429 no provedor

Data: 20/10/2026. Escopo: OrdaX Orchestrator Lab `0.2.0-alpha.2`, perfil Windows staged isolado.

## Evidência física sanitizada

No computador autorizado `DESKTOP-COHT67R`, a rotina read-only existente `test:live:provider-frame` (checkout local `021ba2f`, branch `p5-readonly-evidence-20261020`) observou:

- `readyState=complete`, `bodyPresent=true`, `pageType=conversation`, `mainPresent=true`.
- `composerPresent=false`, `userNodeCount=0`, `assistantNodeCount=0`, `conversationTurnStructuralCount=0`.
- Somente contagens de recursos de mesma origem com prefixo `/backend-api/`: `401=0`, `403=0`, `404=0`, **`429=1`**, `5xx=0`.
- Saída explicitamente identificada como `inspectionOnly=true` e `notAppCertification=true`; não constitui aprovação W3.
- Não foram lidos cookies, tokens, conteúdo de mensagens, parâmetros ou endereços de APIs privadas; nenhum novo prompt enviado.

Amostra anterior do mesmo diagnóstico, documentada na PR #295, havia apresentado zero códigos 429. Isso **não comprova** a causa do DOM vazio, um bloqueio permanente, uma violação de cota ou a identidade da conta. As respostas observadas pelo navegador não são uma lista completa de requisições e podem se referir a recursos carregados antes da inspeção.

## Correção canônica

- Amplia `health()` existente para contar de modo restrito respostas de recurso 429 do provedor, sem URL nem payload.
- Acrescenta `backend_http_429_observed` somente quando o compositor não está utilizável; uma página funcional não é rotulada como bloqueada por um evento passado.
- A interface do OrdaX indica a limitação *observada*, distinta de login e de 403, sem atribuir causalidade nem executar retry, reload, bypass de rate limit ou novo envio.
- O bloqueio de envio incerto permanece, usando `assertProviderSendReadiness()` canônico.
- Testes de política e UI preservam a proteção e o isolamento da conta.

## Critérios de aceite ainda abertos

- **W3:** somente interface OrdaX, mesma Task, URL canônica, mensagem original e resposta atribuível renderizadas. Permanece inconclusivo.
- **W4:** queda real durante geração, recuperação durável sem replay. Ainda não executado.
- A PR #295 de diagnóstico CDP permanece separada, em rascunho; não incorporar alterações não validadas nem tocar no checkout Windows que outro fluxo utiliza.
- OrdaX Flow/Grátis, OS, Runtime e pendrive inalterados. Não promover versão/release.
